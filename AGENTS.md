# Typewright

Native macOS Typst editor (SwiftUI + AppKit, macOS 26+, Liquid Glass). Edist is the design reference.

## Rules

- No markdown files besides `README.md` and `AGENTS.md`. Do not write docs or memory files.
- Keep code comments short (one line, explain why, not what).
- Match surrounding code style. Prefer native Apple controls and look over custom designs.
- Commit messages follow Conventional Commits (`feat:`, `fix:`, `chore:` …); release versions depend on it.

## Layout

Every module lives in its own top-level folder; `scripts/` is shared.

- `macApp/` the SwiftUI/AppKit app: `Typewright.xcodeproj`, `Sources/Typewright`, `Tests/TypewrightTests`, `Resources`. The project uses folder-synchronized groups: files added under `Sources/Typewright` or `Tests/TypewrightTests` are picked up automatically, no pbxproj edits.
  - `Sources/Typewright/App` app entry, window management (`Opener`, `MainWindowController`), spaces sidebar and selector.
  - `Sources/Typewright/Workspace` space model (files, autosave, compile scheduling) and space UI. A space is a folder in the library; `SpaceFolders` creates and imports them, `FileOperations` runs file tree changes with undo.
  - `Sources/Typewright/History` the library: `SpaceRepository` (the jj bridge's Swift side), `CommitScheduler`, file history, conflict resolution, Recently Deleted and the retention settings.
  - `Sources/Typewright/Compiler` built-in compiler (`BuiltinCompiler`), external typst download/selection (`CompilerManager`), `typst watch` driver, diagnostics parsing, font sources (`FontLibrary`).
  - `Sources/Typewright/Editor` NSTextView based editor, highlighting, line numbers, tinymist language server client (`LanguageClient`, completions, go to definition) and color literal swatches with the color wheel.
  - `Sources/Typewright/Editor/Markdown` the Markdown block editor (Notion-like, slash commands): `MarkdownEditor.js`/`.css` in a web view, bundled as resources. Markdown files open in it; their source shows in the preview's place ("Show Editor"). The bridge splits the file into blocks of whole lines (`tw_markdown_blocks`) and a block writes back only its own lines. ```` ```solveng ```` blocks are calculation cells: all of a file's cells compile in order as one worksheet (`tw_markdown_notebook`, imports added for the bindings they use) and show the SVG results.
  - `Sources/Typewright/Preview` PDF (PDFKit), HTML and SVG previews of typst (shown as the inspector pane).
  - `Sources/Shared` code compiled into both the app and the Quick Look extension (font search, Markdown rendering); only system frameworks and `TypstBridge`.
  - `QuickLook` the Finder Quick Look extension (`TypewrightQuickLook.appex`, data based): `.typ` compiled to PDF in process, Markdown as HTML. Its Info.plist and entitlements live in `Resources`.
  - `Sources/Typewright/Sync` device sync: passkey account (`SyncIdentity`), `SyncService` syncing shares as jj nodes, `LiveEditing` (the shown file shared live with other devices, with their cursors), `Invites` ("Share…", `typewright://join/…` links, the library-only destination panel), FSEvents `FolderWatcher`, Devices settings.
- `sharedCore/` Rust logic layer (`typewright-core`), shared by the Mac app and the web app: diagnostics parsing, release picking, UTF-16 text positions and edits, file kinds, paths, space order, fuzzy matching, `.gitignore` rules, share decisions (`shares.rs`), text merges, invite links, path references and highlighting of code in raw blocks. The Mac app gets the `TypewrightCore` Swift module from UniFFI: `scripts/build-sharedCore.sh` (an Xcode build phase) builds the static library, generates the bindings and compiles them with `swiftc`. The web app gets the subset it uses from `web.rs` (wasm-bindgen, records as plain TypeScript objects through tsify), loaded by `webApp/src/lib/core.ts`.
- `webApp/` SolidStart (client only) web app on GitHub Pages: CodeMirror editor, spaces in origin storage (`lib/storage.ts`), typst in a worker (`workers/typst.worker.ts`), sync of shares through the iroh bridge and the jj worker (`lib/sync.ts`, the same loop as the Mac's `SyncService`), passkey account (`lib/identity.ts`). Uses the Rust core and both Rust bridges built for wasm into `src/wasm/` (git-ignored).
- `desktopApp/` the web app as a desktop app for Windows, Linux and macOS: Electron (Chromium, which the web app's OPFS storage is built for; system WebKit fails it, so not Tauri) and electron-builder (`electron-builder.yml`: dmg, NSIS, AppImage, deb, rpm). `main.js` serves the web build from `web/` (git-ignored, copied in by the build script) at `app://typewright/`, a fixed origin so storage survives updates; `preload.cjs` exposes `typewrightDesktop` (`webApp/src/lib/desktop.ts`) for theme sync and macOS's window buttons, which sit in the sidebar's header (`.desktop-mac`). Icons in `build/` come from `scripts/make-icon-desktopApp.sh`. Passkeys don't work there (wrong relying party), so it signs in with the account key. Bun only, no Node: `bunx --bun electron-builder`; electron-builder's icon converter hangs under Bun, hence the pre-made icons.
- `typstBridge/` Rust static library linking typst in process; its `World` serves unsaved buffers from memory. It also carries solveng's editor support (`solveng.rs`: highlighting (the `=`/`->` showing a result is token kind 11, set very bold), completions, hovers, concealing and math ⇄ code block conversions for solveng code blocks, worksheet math and the strings and options of its calls), from the `solveng-ide` crate in the solveng repository (`editor/`, a git dependency on solveng's `main` in `typstBridge/Cargo.toml`; CI runs `scripts/update-solveng.sh`, so every run builds the newest commit on main). Working on that crate locally means an untracked `.cargo/config.toml` with `paths = ["../solveng/editor/ide"]` (committing it breaks CI, which has no sibling checkout; `paths` keeps the `Cargo.lock` files clean, where `[patch]` would rewrite them); the same crate powers the public `solveng-lsp`. Swift reaches it through `SolvengSupport`, the web app through the worker (`lib/editor/solveng.ts`).
- `jjBridge/` Rust static library holding the library, one jj repository (jj-lib, Git backend, colocated on macOS) with every space as a top-level folder: commits, retention squashing (`retention.rs`, `squash.rs`), file history, conflicts, deletions (`deleted.rs`), sync nodes (`nodes.rs`), the managed jj config (`repo_config.toml`) and recovery from whatever the jj CLI left (`normalize.rs`). C API in `include/JJBridge.h` (JSON in and out). Built for wasm32-wasip1 too (`scripts/build-webApp-jj.sh`, patched crates in `vendor/`), run by the web app's `workers/jj.worker.ts` on the OPFS WASI host `lib/wasi.ts`.
- `irohBridge/` Rust static library syncing shares between a user's devices (and invited accounts) with iroh-docs, iroh-blobs and iroh-gossip (`shares.rs`, node bundles in `bundle.rs`), plus live editing of open files (`live.rs`, yrs CRDT over gossip); events reach Swift as JSON through one C callback.
- Both Rust bridges are built by `scripts/build-rust-bridge.sh <crate> <lib>` (needs `cargo`): the typst bridge in the Quick Look extension's build phase (the app depends on it, so it builds first), the iroh and jj bridges in the app's. Their C API lives in `ffi.rs`, the wasm-bindgen API in `web.rs`.
- `scripts/` build phases, icon generation, release build, version calculation, cask generation. Scripts for one module are named after it (`run-macApp.sh`, `run-webApp.sh`, `build-sharedCore.sh`); `build-rust-bridge.sh` and `next-version.sh` serve several.

## Commands

Run from the repository root.

- Build: `xcodebuild -project macApp/Typewright.xcodeproj -scheme Typewright -derivedDataPath .build build`
- Run the dev app: `scripts/run-macApp.sh` (Debug build in the foreground, its logs in the terminal; also the T3 project's "Run Dev App" action)
- Test: `xcodebuild -project macApp/Typewright.xcodeproj -scheme Typewright -derivedDataPath .build test`
- Rust core tests: `cargo test --manifest-path sharedCore/Cargo.toml --target-dir .build/cargo`; the jj bridge's the same with `jjBridge/Cargo.toml` (some drive the `jj` CLI and skip without it)
- Sync over the network (two devices in one process, real n0 relays): `TEST_RUNNER_TYPEWRIGHT_NETWORK_TESTS=1 xcodebuild -project macApp/Typewright.xcodeproj -scheme Typewright -derivedDataPath .build test -only-testing:TypewrightTests/SyncNetworkTests` and `cargo test --release --manifest-path irohBridge/Cargo.toml --target-dir .build/cargo -- --ignored`
- Sync with the web app (this Mac against a headless browser, real n0 relays): run `bun run dev --port 5391` and `bun tests/webpeer.ts <folder> http://localhost:5391/` in `webApp/` (Chromium from `bunx playwright install chromium`), then `TEST_RUNNER_TYPEWRIGHT_WEB_PEER_DIR=<folder> xcodebuild … test -only-testing:TypewrightTests/WebPeerSyncTests`
- Run the desktop app: `scripts/run-desktopApp.sh` (Electron against vite's dev server); installers for this platform: `scripts/build-desktopApp.sh <version>` into `desktopApp/dist`. Unset `ELECTRON_RUN_AS_NODE` (set inside Electron-based hosts) or Electron runs as Node.
- Run the dev web app: `scripts/run-webApp.sh` (builds the wasm, installs packages, starts vite; extra arguments go to vite)
- Web app: `scripts/build-webApp-wasm.sh` (needs Homebrew's `llvm`) first, then `bun install` and `bun run dev` / `bun run check` / `bun run build` in `webApp/`
- Release bundle: `scripts/build-macApp.sh <version>`
- Icon: `swift scripts/make-icon-macApp.swift`

## Gotchas

- Windows are AppKit-managed (`MainWindowController` + `NSHostingController`); one window switches between spaces, or shows none. Don't reintroduce SwiftUI `WindowGroup`.
- Settings use `NSTabViewController` (toolbar style); the SwiftUI `Settings` scene rebuilds its toolbar on tab switches.
- Questions and errors are palette dialogs, not `NSAlert`: `PaletteDialog` runs `message`, `choose`, `input` and `checklist` over the key window in the command palette's look. Spaces and import questions use the window's own overlay (`WindowState.ask`).
- Never create objects with side effects in a view `init` or `@State` default; SwiftUI re-inits views constantly.
- `NSViewRepresentable`s inside split views must implement `sizeThatFits`, or changing fitting sizes crash AppKit's constraint pass.
- New logic goes into `sharedCore/` when it doesn't need the platform. Annotate items with `#[cfg_attr(not(target_arch = "wasm32"), uniffi::export)]` (or `derive(uniffi::Record)`/`Enum`) for Swift; objects and functions taking callbacks live in `ffi.rs`; add what the web app needs to `web.rs`. Swift sees free functions with Rust's names in camel case (`applyTextEdits(edits:text:)`), offsets as `Int32`, methods of records as functions (`range.end()`), and callbacks as `PathCheck` objects (`ExistsIn(root)` checks the disk).
- Core type names can clash with the app's (`Diagnostic`, `FileKind`, `TextEdit`); unqualified names resolve to the Swift ones, so qualify core ones as `TypewrightCore.X`. The same goes for core functions shadowed by a method of the same name.
- Sync, per share and opt-in: a share is a space, or any folder or file in the library, and each device maps its id to its own path there. Every key derives from one 32-byte account secret (a passkey's PRF output, or a recovery key), so devices of an account find each other through a pkarr record and open the same replicas without exchanging anything. Each share's replica (`share replica v1`, from the share's secret) holds `head/<device>` → a node bundle (manifest plus every git object of a jj node, `bundle.rs`; the same node gives the same bytes on every device), `lfs/<blake3>` → LFS files, `name/<device>` → device names for conflict sides. A commit touching a share exports a node (`twj_export_node`) and publishes it; a head this device lacks is fetched, imported and merged 3-way by jj (`twj_merge_node_keeping`), and a clean merge is published again; merge nodes have sorted parents, so devices converge on one id. Conflicts stay jj conflicts until resolved; a resolution from another device replaces them. A share whose path is missing never exports (that would delete it everywhere).
- LFS files (binary, or above the Devices limit, 1 MB default) are never in jj trees; on concurrent changes the newer one wins and the other becomes `name (conflict).ext`. Spaces listed the old way (`space/<id>`, from path-by-path sync before shares) become `share/<id>` entries of kind `space` with the same id and keys; their old replicas are no longer read.
- Sign-in is a passkey, or an account key (the 32-byte account secret as 64 hex digits; "Create" makes a random one, any signed-in device copies its key). The relying party is `TYPEWRIGHT_PASSKEY_DOMAIN` (`bierdav.github.io`), which must serve `/.well-known/apple-app-site-association` listing `G5K3D2J5Y9.dev.bierdav.Typewright` under `webcredentials`. Only `scripts/build-macApp.sh` with `TYPEWRIGHT_SIGN_IDENTITY` and `TYPEWRIGHT_PROVISIONING_PROFILE` signs in the entitlement (the release workflow imports them from secrets and refuses to publish without them or the notary secrets); `SyncIdentity.passkeyDomain` checks the running app's entitlements, so ad-hoc and debug builds have no passkeys and sync only with an account key. Debug builds use Apple Development signing for team `G5K3D2J5Y9` with `Resources/Debug.entitlements`; `scripts/run-macApp.sh` manages provisioning and device registration. The secret lives in the data protection keychain; ad-hoc builds fall back to the file keychain, and signed builds copy legacy credentials on first access. CI uses `CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual TYPEWRIGHT_DEBUG_ENTITLEMENTS=` to keep ad-hoc builds without provisioning.
- Share membership lives in the account replica as `member/<share>/<device>`: "Stop Syncing" removes only this device, a share without members drops off the account, and "Remove From All Devices" writes `removed/<share>`, which makes every device stop (files stay). Spaces synced before shares migrate by id when they're in the library (`syncedSpaces` → `syncedShares`, on the web `typewright.syncedSpaces` → `typewright.syncedShares`); ones outside the library drop out, since only library spaces sync.
- Sharing with other accounts: "Share…" (spaces sidebar, file sidebar, Devices settings, command palette) builds `typewright://join/<base64url>` (`invites.rs` in the Rust core: namespace secret, share id, name, a file flag (version 2 links; folder links stay version 1), up to 3 endpoint ids to dial first) and marks the share `"shared": true` in the account replica. Joining asks for a destination in the library (`LibraryPanel`; on the web the palette's destination page). Joined shares store `"secret"` in the joiner's account entry, so their other devices get it too. Every device syncing a shared share lists itself in a pkarr record keyed by that secret and syncs replica and live topic (`shared live v0`, from the secret) with everyone listed; iroh-docs also redials the last few peers it synced a replica with. Leaving takes only this device out of the record. Anyone with the link can edit. The sharing palette controls device sync (`"devices"`, true by default) separately from links: with device sync off, only `"host"` participates for the account. Replacing or revoking the active link rotates `"owner_key"` in the owner’s account entry, moves its devices to a fresh replica and live topic, and leaves old participants with their existing copies. Saved settings under `key/<id>` preserve device-sync choices and rotated credentials even after the last local copy is deleted and later restored. Joined entries keep `"secret"`; `"owner_key"` does not mark an owner as joined. Account shares can also link to existing spaces; jj merges their contents.
- Live editing: the selected text file of a share joins the share's gossip topic, keyed by the path inside the share (`@file` for a file share). Remote changes queue in Rust until Swift calls `tws_live_sync` with its current text, so edits never interleave with typing; when two sessions meet the older one wins and the other merges its edits in (`TextMerge`). Undo goes through the CRDT and takes back only this device's edits. Files with a live peer keep their content through node merges (the `keep` list of `twj_merge_node_keeping`; conflicts there resolve to the local side).
- The library lives in `~/Library/Application Support/Typewright/Spaces` (the test host uses a temp folder and its own `XDG_CONFIG_HOME`; debug runs take `TYPEWRIGHT_SPACES_ROOT`). Edits are committed 5 s after the last change or every 60 s; old autosaves are thinned out by the retention policy. The bridge writes a managed jj config (`repo_config.toml`, versioned; bump the version line when changing it) explaining all this to people and agents running `jj` there. Folders holding `.jj` aren't spaces; ones holding `.git` stay spaces but jj skips them (no history, no sync).
- File operations (delete, rename, move, add, space rename and delete) commit at once with a descriptive message, and undo does the inverse on disk as a new commit, never `jj undo`. There's no trash: deletions are commits, listed in Recently Deleted (`twj_deleted`), with untracked LFS files kept in a stash under `.jj/typewright/deleted/` for 30 days. Deletions arriving through sync are just the merge's commit, so they show there too.
- Moves post `SpaceRepository.didMove` (call `noteMoved` after moving anything yourself), so shares at or inside the moved item follow it. Deleting a share's root (or a folder or space holding it) parks the share: this device leaves it (`syncParkedShares` keeps its name, kind and secret), and restoring the item (undo, Recently Deleted) lists it again under the same id and syncs.
- Spaces with shares autosave after 1 s instead of 30 s, flush before merges (`SyncService.willChangeFiles`) and reload after (`didChangeFiles`).
- Relative font folders (Settings › Fonts, default `./fonts`) are looked up in the previewed file's folder and every folder above it (`FontSearch`). The app writes the folder settings to `~/Library/Application Support/Typewright/fonts/paths.json`, since the sandboxed Quick Look extension can't read its defaults; the extension reads files through temporary read-only exceptions and keeps typst's package cache in the real home.
- `scripts/build-macApp.sh` signs the extension with its own entitlements before the app; `--deep` would drop its sandbox.
- The built-in typst version is pinned in `typstBridge/Cargo.toml` (`typst = "=x.y.z"`); bump all typst crates together.
- External compilers only see the disk: edits are saved on every keystroke and `typst watch` recompiles. The built-in compiler reads buffers and autosaves every 30 s.
- solveng's settings and definitions can live in other files: `Workspace.solvengContext()` (Mac and web) is a JSON string of the previewed main file and the local files it and the shown file `#import`/`#include`, the last compile's solveng report, the shown file's path and whether it's the main file; every solveng call takes it.
- solveng's `worksheet` leaves `<solveng>` metadata per equation and code element; the typst bridge collects it after each built-in compile (`solveng_report`, `tw_world_solveng`, `CompileResult.solveng` on the web). Its integration decides what's calculated and its computed values become completion details; without a report nothing is (outside equations passed to `#worksheet(…)`). A shown file the preview doesn't reach, and the previewed file under an external compiler, are compiled by the built-in compiler without output (`TWFormatCheck`, format 3 on the web) just for the report (`fileReport` in the context).
- The typst CLI is downloaded to `~/Library/Application Support/Typewright/compilers/<version>/typst`.
- tinymist (the language server) is downloaded to `~/Library/Application Support/Typewright/tinymist/tinymist`; a Homebrew install wins. One process runs per open space and gets full-text `didChange`s.

- The web app derives the same account from the same passkey only on the relying party's domain, so it's hosted at `invites::WEB_APP` (`bierdav.github.io/typewright`). The tab running the jj repository runs the sync node too (Web Locks); other tabs show "Syncing in another tab". Node objects and LFS files pass between the node and the jj worker through `.jj/typewright/transport/` in origin storage; the browser keeps blobs in memory, so its replicas' snapshot (`replicas.bin`) carries only small ones and LFS files are seeded again from the files on each publish after a reload.
- Web invite links are `<web app>/join#<payload>`; GitHub Pages serves `404.html` (the app) for `/join`.

## Releases

Run the `Release` workflow in GitHub Actions. Pick `alpha`, `rc` or `stable`, and tick `major` for breaking releases. `scripts/next-version.sh` computes the version from the last stable tag: a major bump if `major` is ticked, a minor bump if a `feat` commit landed since that tag, a patch bump otherwise. Pre-releases get `-alpha.N` / `-rc.N`. The workflow builds, creates the GitHub release, attaches the desktop app's installers (built on macOS, Windows and Linux runners from one web build) and updates `Casks/typewright.rb` (stable) and `Casks/typewright@beta.rb` (every channel) in `BierDav/homebrew-tap`.

The `Web App` workflow deploys `webApp/` to GitHub Pages on every push to `main` that touches it, the Rust core or the bridges (Pages has to be set to "GitHub Actions" in the repository settings).
